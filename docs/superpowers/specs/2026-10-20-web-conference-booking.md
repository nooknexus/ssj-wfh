# ข้อกำหนดระบบจอง Web Conference

**ที่มา:** `WEB_CONFERENCE_PLAN.md` ซึ่งเจ้าของผลิตภัณฑ์ส่งให้เมื่อ 20 ตุลาคม 2026

## เป้าหมาย

ปรับระบบจองห้องประชุมจริงเป็นระบบจองลิงก์ Web Conference ที่ตั้งชื่อได้ ผู้ใช้เลือกวัน เวลาเริ่ม/สิ้นสุด และจำนวนผู้เข้าร่วม ระบบจะแสดงลิงก์ที่ใช้ได้ในช่วงเวลานั้น แล้วสร้างคำขอที่รอการอนุมัติ ผู้ดูแล IT และผู้ดูแลระบบสูงสุดจัดการลิงก์และอนุมัติหรือไม่อนุมัติการจองได้

## ข้อมูลและกฎที่ต้องคงไว้

- แทน `meeting_rooms` ด้วย `conference_links` ซึ่งเก็บชื่อ, `ConferencePlatform` (`zoom`, `teams`, `meet`, `webex`, `other`), URL, จำนวนผู้เข้าร่วมสูงสุด (ถ้ามี), รายละเอียด, สถานะเปิดใช้งาน และลำดับแสดงผล
- แทน `date`, `start_time`, `end_time` ของการจองด้วย `start_at` และ `end_at` แบบวันเวลาสมบูรณ์ โดยยังคงสถานะและข้อมูลการอนุมัติ
- migration ต้องหยุดก่อนทำลายข้อมูลหาก `meeting_rooms` หรือ `meeting_bookings` มีข้อมูลอยู่ ฐานข้อมูลพัฒนาปัจจุบันว่าง
- ช่วงเวลาชนกันเมื่อ `a.start < b.end && b.start < a.end` รายการ `pending` และ `approved` กันช่วงเวลา ส่วน `rejected` และ `cancelled` ไม่กัน
- เวลาสิ้นสุดต้องหลังเวลาเริ่ม ระยะเวลาต้องไม่เกิน 8 ชั่วโมง เวลาเริ่มต้องไม่เป็นอดีต จำนวนผู้เข้าร่วมต้องมากกว่า 0 และต้องไม่เกินความจุของลิงก์ (หากกำหนดไว้) เลือกเวลาได้ทุก 30 นาทีระหว่าง 07:00–20:00

## สิทธิ์และการเปิดเผยข้อมูล

- ผู้ใช้ที่เข้าสู่ระบบทุกคนดูความพร้อมและตารางรายวัน สร้างการจอง และดู/ยกเลิกเฉพาะการจองของตนได้
- เฉพาะ `itadmin` และ `superadmin` ดูการจองทั้งหมด เปลี่ยนสถานะการจอง หรือเพิ่ม/แก้ไข/ปิดใช้งานลิงก์ได้
- การอนุมัติต้องตรวจเวลาชนกันอีกครั้งภายใน transaction ผู้ใช้ยกเลิกได้เฉพาะรายการที่ยังไม่ถึงเวลาเริ่ม
- คืน URL เฉพาะรายการที่อนุมัติแล้วและเป็นของผู้เรียก ตารางรายวันห้ามคืน URL ทุกกรณี

## หน้าจอ

- `/meeting`: ฟอร์มเดียวสำหรับเลือกวัน เวลาเริ่ม/สิ้นสุด จำนวนผู้เข้าร่วม ลิงก์ หัวข้อ และรายละเอียด พร้อมตารางของวันที่เลือก
- `/meeting/my-bookings`: สถานะ เหตุผลที่ไม่อนุมัติ ปุ่มยกเลิก และปุ่มเปิด/คัดลอกลิงก์เมื่ออนุมัติแล้วเท่านั้น
- `/admin/meeting`: แท็บอนุมัติ/ดูการจองทั้งหมด และแท็บจัดการลิงก์
- เมนูผู้ดูแลแสดงการจัดการ Web Conference แก่ IT admin และ superadmin และเลิกใช้ flow เดิมที่ `/meeting/book`

## การตรวจสอบที่จำเป็น

- Unit test ครอบคลุมเวลาชนกัน สถานะที่กันเวลา validation ความจุ และช่วงเวลา 30 นาที
- API test ครอบคลุมสิทธิ์ เจ้าของรายการ การปิดบัง URL การยกเลิก และเวลาชนกันขณะอนุมัติ
- รัน typecheck, test suite, build และ migration กับฐานข้อมูลพัฒนาหลังสำรองข้อมูลแล้ว รวมถึงทดสอบ browser ตามสถานการณ์ในแผนต้นฉบับ
